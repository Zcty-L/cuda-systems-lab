# FP32 opt 与 baseline 对比

> 以下为 bias 调整前的历史测量。当前 FP32、FP16 opt 已改为直接读取 bias 初始化累加器，移除了 shared bias 及专用同步，尚未重测性能；下表资源与耗时不代表修改后的版本。

对比 `conv2d_4x128x256_groups_kernel` 与 `dwconv_opt_fp32.cu` 的 `launch_opt_fp32` 自动分派。baseline 已删除循环内冗余同步；两者使用相同输入、权重、bias 和输出布局。

## 测量方法

- 设备：RTX 5070 Ti Laptop，SM 12.0，46 SM，36 MiB L2；CUDA 13.2，Release 构建。未锁频，存在明显波动。
- NCHW、depthwise multiplier=1、dilation=1、H=W、Kh=Kw=K、padding=K/2。表中 S 为 stride。
- 每版先直接预热 20 次，再执行一次 100 节点 CUDA Graph；随后测 10 轮，每轮交替先后顺序。CUDA event 测量整个图，除以 100 得到单次耗时，包含图内节点调度，不包含 CPU 分派、分配和传输。
- 同一地址重复执行，属于预热后的重复输入测量；大工作集不保证全部驻留缓存。完整扫描独立执行两次，表列各次中位数；加速比为 baseline / opt，大于 1 表示 opt 更快。
- 小输入 N1/C32/H28；C348/692/1380、H64 对应 baseline 约 5/10/20 waves；大输入 N8/16/32、C64、H128；另测 N16/C128/H128、S2。实际 opt grid、资源与 waves 从捕获的 kernel 节点读取，记录在日志。
- `dwconv_test` 使用独立 CPU 参考验证；基准每组还比较所有输出，要求有限且误差不超过 `1e-5 * (1 + abs(baseline))`。性能输入为 `(i % 29 - 14) / 32`。

FP32 opt 新增可选 stream 参数（默认仍为默认流），便于两版在同一流上捕获和计时，未修改 kernel 计算或分派阈值。

## 结果

38 组配置在两次扫描中全部通过结果对比，独立 CPU 参考测试通过。

- **11×11 收益最大**：所有配置为 1.79～2.34×；N16/C64/H128/S1 两次为 2.27×、2.09×，N32 为 2.19×、2.12×。
- 3×3、5×5 在 S1 的全部配置中，中位数均优于 baseline；大输入分别约 1.05～1.21×、1.13～1.19×。S2 的 3×3 两次则慢约 2～3%，幅度较小。
- 7×7 小输入触发单通道 kernel，两次慢 19.4%、20.7%；其余配置约 0.98～1.11×，小幅收益需要更稳定的计时条件确认。
- 9×9 使用通用回退路径，中大输入两次均未取得收益，约 0.87～0.99×。不能把 opt 当作全配置替代品。

两次扫描绝对耗时存在明显漂移。例如 N1/C348/H64/K11，baseline 中位数从 388.35 变为 222.50 μs，opt 从 211.09 变为 124.34 μs。因此只比较每次扫描内部相同配置的两版，不用跨次绝对差异解释优化。

## 实现与资源

本测试比较的是完整 opt 分派，不能将收益归因于单一修改。3/5/7 的四通道 kernel 对核尺寸进行模板特化；小输入 7×7 改用单通道；11×11 将输入 tile 加载到 shared memory 后重复使用；9×9 走通用分支。opt 通用/特化四通道路径还在 shared memory 中广播 bias，并有一次额外同步。

本次所有 kernel 都是 256 threads/block，无 local memory：

| 路径 | registers/thread | shared/block（字节） | blocks/SM |
| --- | ---: | ---: | ---: |
| baseline | 40 | 2048 | 6 |
| opt 四通道 3/5/7、通用 9 | 40 | 2064 | 6 |
| opt 单通道 7 | 28 | 208 | 6 |
| opt shared-input 11，S1 | 38 | 13296（动态） | 6 |
| opt shared-input 11，S2 | 38 | 29616（动态） | 3 |

S1 的 11×11 在 blocks/SM 不变时明显加速；S2 虽降至 3 blocks/SM，仍达到 2.18～2.31×。这说明仅看驻留 block 数无法判断性能。本次未采集 NCU 指令或缓存指标，不进一步作瓶颈归因。

## 复现

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target device_query dwconv_test dwconv_opt_bench -j8
mkdir -p build/dwconv-opt
./build/tools/device_query > build/dwconv-opt/device.log
ctest --test-dir build -R '^dwconv_test$' --output-on-failure
./build/benchmarks/operators/dwconv_opt_bench > build/dwconv-opt/run1.log
./build/benchmarks/operators/dwconv_opt_bench > build/dwconv-opt/run2.log
```

原始数据位于 `build/dwconv-opt/`：两次扫描包含全部逐轮样本、中位数和 min/max，以及 grid、工作集、资源、waves；另保留设备信息、正确性日志及源码和可执行文件 SHA256。
