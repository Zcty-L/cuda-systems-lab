# DWConv FP16：baseline 与 prefetch 测量

两次扫描中，小输入 `N=1,C=32,H=W=28` 的 prefetch 中位耗时降低约 12%–20%；大 batch 收益明显缩小，不能作为普遍更快的替代：

- `C=64,H=W=128,S=1`：N=8/16 的 K=7/11 约降低 1%–1.5%；N=32、K=11 降低 1.26%/1.65%。
- N=32、K=7 反而慢 6.38%/2.66%；N=16/32、K=3 接近持平或略慢。
- `N=16,C=128,H=W=128,S=2`：K=11 降低 3.85%/4.47%。

许多配置的轮间波动超过版本中位数差异；小输入跨扫描的绝对耗时也显著变化。以上是本次未锁频条件下的观察，不能据此承诺稳定加速或归因为 blocks/SM。

## 配置与方法

2026-10-10，RTX 5070 Ti Laptop（SM120，46 SM，36 MiB L2），驱动 596.21、CUDA 13.2，CMake Release。比较 `launch_baseline_fp16_k128` 与 `launch_prefetch_fp16_k128`，`Conv2DParam` 字段均为 `int`。

输入为连续 NCHW FP16，权重预先打包为 half2，bias 初始化累加器，逐 tap 执行 FP16 FMA。两版权重均一次加载，输入加载与边界语义相同；prefetch 使用 A/B 输入寄存器片段，每轮展开 8 tap。两版均仅在加载权重后同步。

每配置先检查两版全部输出数值完全一致且有限，再分别直接预热 20 次、预热一次 100 节点 CUDA Graph。使用同一 stream，10 轮交替 baseline/prefetch 顺序，每轮 CUDA Event 测量 100 次 kernel 序列，除以 100，报告中位数及最小/最大值；每版均在 5 轮中先运行。完整扫描重复两次，串行执行。计时不含分配、上传、权重打包、校验与构图。

所有配置 W=H，padding=K/2，block=256，grid=(ceil(outHW/256),C/8,N)。重复使用相同缓冲区，缓存可复用，不主动清缓存；大工作集不保证全部驻留 L2。使用默认 shared carveout，设备承担显示且未锁频，波动需结合两次扫描判断。1 秒间隔遥测覆盖第一轮后半段及第二轮；GPU 利用率至少 90% 的 72 个样本中，核心频率为 1110–2122 MHz、显存频率为 9001–14001 MHz、温度为 55–66°C，不能视为固定时钟实验。

| 资源 | baseline | prefetch |
| --- | ---: | ---: |
| registers/thread | 40 | 55 |
| shared/block | 2048 B | 2048 B |
| local/thread | 0 B | 0 B |
| 理论 blocks/SM | 6 | 4 |

资源由运行时 API 查询；驻留量减少本身不能证明是性能差异的原因，本次没有做瓶颈归因实验。

## 复现

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target dwconv_fp16_bench dwconv_fp16_test -j 8
./build/tools/device_query
ctest --test-dir build -R '^dwconv_fp16_test$' --output-on-failure
mkdir -p build/dwconv-fp16-prefetch
./build/benchmarks/operators/dwconv_fp16_bench > build/dwconv-fp16-prefetch/run1.log
./build/benchmarks/operators/dwconv_fp16_bench > build/dwconv-fp16-prefetch/run2.log
```

19 组 CPU 参考正确性测试通过；两次扫描均对所有测速配置进行输出一致性校验。逐轮数据、设备信息和采样期间的时钟记录保存在忽略目录 `build/dwconv-fp16-prefetch/`。`summary` 行依次为 N、C、H、K、stride、版本、中位数、最小值、最大值，单位 µs。
