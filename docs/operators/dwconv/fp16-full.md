# FP16 全量前向对比

## 配置与口径

使用与 [FP32 全量测试](fp32-full.md) 相同的 653 个 shape：23 个快速用例，以及 N={1,2,4,8,16,32,64}、C={32,64,128,256,512,1024}、H=W={40,80,160}、K={3,5,7,9,11} 的 630 个组合。stride=1，padding=K/2，包含 bias，布局为 NCHW。

比较 baseline 自动分派、opt、抽离的 PyTorch CUDA 前向和 cuDNN Graph Conv→ADD。FP16 输入、权重和输出，FP32 乘加与累加，写回时舍入；PyTorch 项不经过框架调度。baseline 根据 K² 分派 k32/k64/k128，block=256，grid=(ceil(HW/256), C/8, N)。

四种实现单 GPU 串行测量，同一 shape 相邻执行，并随 case 轮换顺序。每项独立进程，预热 20 次、计时 100 次，CUDA Event 测量连续 launch 平均耗时，包含卷积和 bias，不包含数据准备、分配、H2D、权重打包、cuDNN plan 准备及释放。准备与释放耗时单独记录。CPU 校验关闭，本轮只确认 CUDA 执行成功，不代表全量数值正确性验证。

设备：RTX 5070 Ti Laptop GPU，SM 12.0，46 SM，11.94 GiB 显存、36 MiB L2；CUDA 13.2、cuDNN 9.23.1，WSL2。测试日期为 2026-10-13。最大配置输入输出合计 6.25 GiB，低于物理显存容量。不锁频、不清缓存，重复访问相同分配；未测 occupancy/waves。仅扫描一轮，短 kernel 可能包含主机提交间隙，不能以几个百分点差异判断稳定收益。

`relative_to_cudnn = kernel_us / cudnn_us`，cuDNN 为 **1.0**，越小越快。cuDNN 使用 heuristic 选择 plan，未穷举 engine。

## 复现与产物

```bash
cmake --build build --target dwconv_test device_query -j 4
conda activate py311
python benchmarks/operators/dwconv_full_bench.py --dtype fp16 --include-opt
```

结果保存至 `build/dwconv-full-fp16/`：`summary.csv` 每行一个 shape/kernel，记录状态、kernel 微秒数、相对耗时、prepare/post 毫秒数及 cuDNN engine/workspace；`comparison.csv` 每行一个 shape，横向比较四种实现；`aggregates.csv` 按 K 汇总规则网格的相对耗时中位数。原始命令和输出位于 `case-<ID>-<kernel>.log`，配置与二进制 SHA256 位于 `config.json`，另存 `cases.txt` 和 `device.txt`。相同命令支持续跑，FP32 结果保存在独立目录。

正式归档：[summary.csv](results/2026-10-13-rtx5070ti-laptop/fp16/summary.csv) · [comparison.csv](results/2026-10-13-rtx5070ti-laptop/fp16/comparison.csv) · [aggregates.csv](results/2026-10-13-rtx5070ti-laptop/fp16/aggregates.csv)；配置、设备信息、用例列表及五张图片见[实验归档](results/2026-10-13-rtx5070ti-laptop/README.md)。上述 `build/` 路径为运行与续跑目录，逐用例日志保留在其中。

## 结果

完成全部 653 个配置，记录 2,612 项：**2,608 项执行成功、4 项不支持、0 项执行失败**。不支持项为 case 15（C=4）和 case 16（C=36）的 baseline、opt，原因是现有 FP16 接口要求 C%8=0；这两个 shape 的 cuDNN 和 PyTorch 正常完成。没有为不支持项填入耗时或替代实现。cuDNN 全部选中 engine=0、workspace=0。

以下统计包含全部 630 个规则网格配置，每种 K 有 126 个；不计 23 个快速用例，避免重复 shape 和不同形状分布影响统计。与 FP32 报告不同，本轮所有输入输出均未超过物理显存，因此无需排除最大配置。数值为逐 shape 相对 cuDNN 耗时的中位数，越小越快。

| 卷积核 | shape 数 | cuDNN | baseline | PyTorch | opt |
| --- | ---: | ---: | ---: | ---: | ---: |
| 3×3 | 126 | 1.0 | 0.371 | 0.630 | 0.318 |
| 5×5 | 126 | 1.0 | 0.552 | 0.833 | 0.715 |
| 7×7 | 126 | 1.0 | 0.622 | 0.686 | 0.901 |
| 9×9 | 126 | 1.0 | 0.716 | 0.971 | 0.256 |
| 11×11 | 126 | 1.0 | 0.732 | 0.868 | 0.259 |
| 全部 | 630 | 1.0 | 0.639 | 0.816 | 0.361 |

四种实现的性能排序随 K 变化。opt 在 9×9、11×11 的相对耗时中位数约为 cuDNN 的 0.256、0.259；5×5、7×7 则是 baseline 更快。不能将“opt”名称理解为所有输入上的最优实现。

直接按每个 shape 计算 opt / baseline 后再取中位数如下；不能用上表两个中位数相除代替。

| 卷积核 | opt / baseline 耗时中位数 |
| --- | ---: |
| 3×3 | 0.872 |
| 5×5 | 1.304 |
| 7×7 | 1.477 |
| 9×9 | 0.364 |
| 11×11 | 0.358 |

本轮 opt 相对 baseline：3×3 中位比值降低约 12.8%；5×5、7×7 分别增加约 30.4%、47.7%；9×9、11×11 分别降低约 63.6%、64.2%。这些是单轮实测分布，不是置信区间。opt 3/5/7 使用 pair 路径，9×9 在 pair_blocks≥140 且共享内存条件满足时使用 shared-input，否则使用 pair；11×11 在共享内存条件满足时使用 shared-input。本轮未做指令或内存分析，不将分派差异直接作为性能差异的因果证明。
