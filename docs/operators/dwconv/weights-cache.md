# DWConv FP32：权重策略相对 baseline 的对照

## 实现

统一以当前 `conv2d_4x128x256_groups_kernel` 为基准：权重合作加载到 2 KiB shared，仅初始化后同步一次，循环内无同步。`dwconv.cu` 中的权重缓存实验提供 gmem 和 gmem_l2 两个 kernel 入口，共用内联计算函数，避免实现分叉。

| 版本 | 相对 baseline 的修改 | weights 缓存策略 |
| --- | --- | --- |
| baseline | 无 | 全局加载一次到 shared，随后读取 shared |
| gmem | 删除权重 shared 存储和初始化同步，每轮直接 `__ldg` 读取权重 | 默认 |
| gmem_l2 | 与 gmem 相同，额外配置 weights 的 L2 窗口 | 优先保留 L2 |

两个版本都保留 baseline 的输入地址计算、空间边界、bias 初始化、每轮 4 tap、累加顺序及输出方式。超出 `KhKw` 的尾部权重补零。约束仍为 FP32 NCHW、C 为 4 的倍数、Kh×Kw≤128、dilation=1。

`gmem_l2` 的计算代码与 `gmem` 相同，L2 属性由启动方配置：直接启动使用 stream `accessPolicyWindow`，CUDA Graph 使用每个 kernel node 的同名属性。窗口仅覆盖 weights，`hitRatio=1`、`hitProp=Persisting`、`missProp=Normal`；input 保持默认策略。仅调用带 `_l2` 后缀的 kernel 不会自动开启策略。优先保留不等于锁定缓存行，也不保证命中。

## 测量方法

2026-10-10，RTX 5070 Ti Laptop，SM120、46 SM、36 MiB L2，CUDA 13.2，CMake Release。block=256，grid=(ceil(outHW/256),C/4,N)，H=W，padding=K/2。GPU 未锁频，无主动清缓存。

三个版本统一设置 L2 set-aside：申请 1 MiB，实际返回 2.25 MiB；只有 gmem_l2 启用权重窗口。每版先执行 20 次直接预热及 100 节点图预热。随后进行 12 轮轮换顺序测量，每版每轮先重置 L2 优先保留属性、预热本版 100 节点图，再使用 CUDA Event 计时 100 次 kernel。重置属性不清空全部缓存。记录每次启动的中位耗时，不含分配、传输、构图、策略配置和预热。重复两次完整扫描。

所有性能百分比均为 `(版本耗时 / 同轮 baseline 耗时 - 1) × 100%`，负值表示更快。以下数据重新测量了删除循环内冗余同步后的 baseline；旧报告中的数据不混入本表。

| 实测资源 | baseline | gmem | gmem_l2 |
| --- | ---: | ---: | ---: |
| registers/thread | 40 | 48 | 48 |
| shared/block | 2048 B | 0 B | 0 B |
| local/thread | 0 B | 0 B | 0 B |
| 理论 blocks/SM | 6 | 5 | 5 |

无 shared 不代表更高驻留量；两个 gmem 版本的寄存器更多。此处没有单独控制驻留量，不能把耗时变化全归因为 blocks/SM。

## 解释与验证

gmem 将每轮四个通道的权重读取从 4 条 `LDS.128` 替换为最多 16 条标量全局加载，并增加地址及尾部判断；缓存命中并不能消除这些指令。反汇编确认当前 gmem 与 gmem_l2 的 SASS 指令序列相同，因此两者间的差异来自缓存配置及运行波动，而不是计算代码不同。相对 baseline 的变化则还包含加载指令、寄存器和驻留量变化，不能只归因为权重被 input 挤出缓存。

`dwconv_test` 通过，包括两个 gmem 计算入口。两轮扫描均检查三个版本全部输出有限且逐元素一致；小输入与 CPU 全量比较，大输入抽样 257 个输出与 CPU 逐 tap FMA 比较，误差限为 1e-5。启用 L2 策略后的正确性由基准程序覆盖。

```bash
cmake --build build --target dwconv_weights_bench dwconv_test device_query -j 8
./build/tools/device_query
ctest --test-dir build -R '^dwconv_test$' --output-on-failure
mkdir -p build/dwconv-weights-baseline
./build/benchmarks/operators/dwconv_weights_bench > build/dwconv-weights-baseline/run1.log
./build/benchmarks/operators/dwconv_weights_bench > build/dwconv-weights-baseline/run2.log
```

`--k3` 单独计时 N=16/C=64/H=W=128/K=3；`--profile` 与 `--profile-k3` 分别只运行 K=7、K=3 的三版正确性启动，供 NCU 使用。旧的 `--persist*` 分支已合并到默认三版对照。

本次原始记录位于本地忽略目录 `build/dwconv-weights-baseline/`：两轮日志包含每个样本、资源、工作集、中位数和 min–max；另有 `device.log`、`test.log`、`sass.txt`、`sha256.txt`。旧的 `build/dwconv-weights/` 和 `build/dwconv-persist/` 只作历史记录，不代表当前 baseline 性能。
