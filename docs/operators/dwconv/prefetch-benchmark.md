# FP32 baseline 与输入预取范围测量

本文保留重写前版本的历史结果；当前实现与新测量见[prefetch 与 baseline 对比](prefetch-matched.md)。

测量日期：2026-10-10。当前 `feature/dwconv` 工作树，未提交版本。只测量既有 kernel，没有修改计算实现。

后续的同机器码驻留限制实验、NCU 与 SASS 证据见[原因诊断](prefetch-matched.md)。下文的寄存器解释仅是初步假设；后续验证显示 7×7/11×11 的退化不能主要归因于 blocks/SM 下降。

## 结论

当前 prefetch 不能替代 baseline 作为普遍更快的实现。在 64×64、stride=1 的全部 12 个配置中，两次扫描的 prefetch 中位耗时均高于 baseline，增加约 5%–17%。

小输入 N=1,C=32,H=W=28,K=3 的 prefetch 中位耗时两次分别减少 6.9%、10.0%，可作为后续复核候选，但不足以据此建立分派规则。K=5 小输入的结论两次反转；stride=2,K=3 的波动同样很大。

## 环境与计时口径

- NVIDIA GeForce RTX 5070 Ti Laptop GPU，SM 12.0，46 SM，L2 36 MiB；CUDA Runtime/Driver API 13.2，nvidia-smi 报告主机驱动 596.21。
- Release CMake 构建。使用 device_query 确认设备后运行。显示输出开启，未锁时钟、未修改功耗限制。
- 1 秒间隔遥测中，高负载阶段观察到 SM 时钟约 885–2302 MHz、显存时钟 11001/14001 MHz，温度约 53–61℃。存在动态频率和显示负载影响；未把波动全部归因于单一原因。
- FP32 连续 NCHW，groups=C，bias 开启，方形卷积核，padding=K/2，dilation=1。同配置三个实现使用完全相同的输入、输出地址、grid 和 block。
- 每版本先直接预热 20 次，再预热一次含 100 个顺序 kernel 节点的 CUDA Graph。每配置测量 9 轮，每轮轮换版本顺序，本文仅保留 baseline 与 prefetch 数据。
- CUDA event 包围一次 graph launch，以图总耗时除以 100，报告单次平均耗时的 9 轮中位数及 min/max。包含图内节点调度间隔，不是 isolated kernel 的 profiler duration。排除分配、拷贝、正确性校验、图创建及 CPU 同步时间。
- 重复执行同一工作集，不清缓存；这是缓存经过预热后的重复调用场景，并不表示所有数据驻留 L2。全流程独立执行两次，每次 20 组配置。
- 原有 17 组 CPU 参考正确性测试全部通过，包括用户修复后的 k32；基准中各形状额外完整比较 prefetch 与 baseline 的输出，全部通过。

## 复现

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target device_query dwconv_test dwconv_bench --parallel
./build/tools/device_query
ctest --test-dir build -R '^dwconv_test$' --output-on-failure
mkdir -p build/dwconv-bench
./build/benchmarks/operators/dwconv_bench > build/dwconv-bench/run1.log
./build/benchmarks/operators/dwconv_bench > build/dwconv-bench/run2.log
```

可另开终端运行 `nvidia-smi --query-gpu=timestamp,temperature.gpu,clocks.sm,clocks.mem,power.draw,utilization.gpu --format=csv -l 1` 记录遥测，测量后结束。原始逐轮数据及遥测仅保存在被忽略的 `build/dwconv-bench/`。

基准入口：[dwconv_bench.cu](../../../benchmarks/operators/dwconv_bench.cu)。后续若继续优化，优先检查寄存器占用与实际指令调度；此次结果不支持直接认定输入预取方案更快。

## H=W=128 大 batch 补充测量

2026-10-10 新增 `--large-batch` 扫描，独立运行两次，硬件与计时方法同上：每配置 9 轮，每版本每轮 100 次，顺序轮换，20 次直接预热及一次图预热；两个完整扫描中，全部 13 组的 prefetch 输出均与 baseline 一致。未修改 kernel。

输入固定 H=W=128。C=64 扫描 N=8/16/32、K=3/7/11、stride=1；另外 N=16,C=128 扫描 K=3/7、stride=1/2。padding=K/2；stride=1 输出为 128×128，stride=2 输出为 64×64。
