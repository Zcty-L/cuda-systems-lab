# FP32 全量前向对比

## 配置与口径

测试 `dwconv_test` 全部 653 个 shape：23 个快速用例，以及 N={1,2,4,8,16,32,64}、C={32,64,128,256,512,1024}、H=W={40,80,160}、K={3,5,7,9,11} 的 630 个组合。stride=1，padding=K/2，包含 bias。保留快速集合中的重复 shape，按 case ID 区分。

- FP32、NCHW；比较 baseline 自动分派、opt、抽离的 PyTorch CUDA 前向以及 cuDNN Graph Conv→ADD。这里的 PyTorch 不经过 PyTorch 框架调度。
- baseline 根据 K² 选择 k32/k64/k128，block=256，grid=(ceil(HW/256), C/4, N)。PyTorch block=256，grid=min(65535, ceil(NCHW/256))。cuDNN 由 heuristic 选择 plan。
- 最初三种实现单 GPU 串行运行，每 shape 三个实现相邻执行，随 case 轮换顺序；opt 随后单独补测。每项独立进程，预热 20 次、计时 100 次；本轮只做一次全量扫描。
- CUDA Event 测量连续 launch 的平均微秒数，包含卷积和 bias；不包含主机生成、分配、H2D、cuDNN plan/workspace 准备及释放。另存 preprocess、postprocess 的主机耗时。
- CPU 校验关闭，本次只检查 CUDA 执行成功；不将本轮标记为全量数值正确性验证。短 kernel 可能受主机提交间隙影响。
- `relative_to_cudnn = kernel_us / cudnn_us`：cuDNN 固定为 **1.0**，小于 1 表示比 cuDNN 快。不是加速比的倒数定义。
- 不锁频、不清缓存，重复访问同一组分配；未测 occupancy/waves，也不据此推断瓶颈。一次扫描不足以判断几个百分点的差异。

设备为 RTX 5070 Ti Laptop GPU，SM 12.0，46 SM，11.94 GiB 显存、36 MiB L2；CUDA 13.2、cuDNN 9.23.1。系统为 WSL2。最大 shape 的输入和输出合计 12.5 GiB，超过物理显存容量，但当前环境实际允许分配和执行。该类结果单独标记，可能包含内存迁移影响，不能视为全部数据驻留显存的性能；本次未采集迁移计数。

## 复现与结果文件

```bash
cmake --build build --target dwconv_test device_query -j 8
conda activate py311
python benchmarks/operators/dwconv_full_bench.py
# 复用已有日志，仅补测 opt
python benchmarks/operators/dwconv_full_bench.py --include-opt
```

结果保存在 `build/dwconv-full-fp32/`：`comparison.csv` 每行一个 shape，横向列出四种实现的原始耗时、相对耗时及容量标记；`aggregates.csv` 保存容量内规则网格按 K 分组的相对耗时中位数；`summary.csv` 每行一个 shape/kernel，包含形状、状态、原始微秒数、相对 cuDNN 耗时及准备/释放毫秒数；`case-<ID>-<kernel>.log` 保存命令和原始输出，`cases.txt` 保存形状列表，`device.txt` 保存设备信息，`config.json` 保存参数及测试二进制 SHA256。每个 shape 完成后刷新 CSV，中断后同配置可续跑；不同二进制或参数须更换输出目录。

正式归档：[summary.csv](results/2026-10-13-rtx5070ti-laptop/fp32/summary.csv) · [comparison.csv](results/2026-10-13-rtx5070ti-laptop/fp32/comparison.csv) · [aggregates.csv](results/2026-10-13-rtx5070ti-laptop/fp32/aggregates.csv)；配置、设备信息、用例列表及五张图片见[实验归档](results/2026-10-13-rtx5070ti-laptop/README.md)。上述 `build/` 路径为运行与续跑目录，逐用例日志保留在其中。

## 结果

完成 653 个 shape，原有 1,959 项测量加上 653 项 opt 补测，共 2,612 项 FP32 前向测量，全部 CUDA 执行成功，无失败或跳过；未开启 CPU 数值校验。cuDNN 全部选择 engine=0、workspace=0。

测量日期为 2026-10-12 至 2026-10-13，因中断分两次完成，二进制 SHA256 和参数保持一致。case 0–633 来自第一次运行，case 634–652 来自续跑；中断跨越的 case 634 已将三个实现一起重测，原记录保存在 `interrupted-case-634/`。未锁频，跨会话温度及频率变化未作校正。

opt 于 2026-10-13 单独补测，设备、二进制、输入和计时参数一致，复用已保存的 cuDNN 耗时归一化，未交错重测 cuDNN。原三种实现的 1,959 条数据逐项验证完全不变，补测前的 CSV 与配置保存在 `before-opt/`。本次未做 CPU 校验；补测间的频率、温度变化可能影响小幅差异。opt 3/5/7 使用专门化路径（7×7 小网格有单通道分派），9×9 使用通用路径，11×11 使用 shared-input 路径。

以下统计仅使用规则网格中的 625 个容量内组合（每个 K 有 125 个）：不计 23 个快速用例，也不计 5 个输入输出超过物理显存的最大配置。表中数值为逐 shape 相对耗时的中位数，越小越快。

| 卷积核 | shape 数 | cuDNN | baseline | PyTorch | opt |
| --- | ---: | ---: | ---: | ---: | ---: |
| 3×3 | 125 | 1.0 | 0.414 | 0.605 | 0.393 |
| 5×5 | 125 | 1.0 | 0.587 | 0.794 | 0.565 |
| 7×7 | 125 | 1.0 | 0.656 | 0.672 | 0.667 |
| 9×9 | 125 | 1.0 | 0.788 | 1.001 | 0.821 |
| 11×11 | 125 | 1.0 | 0.811 | 0.882 | 0.430 |
| 全部 | 625 | 1.0 | 0.691 | 0.807 | 0.568 |

baseline 的相对耗时中位数在五种卷积核下均低于 cuDNN；PyTorch 在 9×9 下约为 1.001，其余四组中位数低于 cuDNN。这是当前设备与所选 cuDNN heuristic plan 的结果，不代表穷举 cuDNN engine 后的最优表现。

625 个组合中，baseline 有 608 个比 cuDNN 耗时低超过 5%，5 个在 ±5% 内，12 个高超过 5%；PyTorch 分别为 510、69、46 个。这里只描述单轮样本分布，5% 分类不代表统计显著性。包含全部 653 个 shape 时，两者相对耗时中位数分别为 0.692、0.807。

opt 在容量内网格中的相对 cuDNN 耗时中位数为 **0.568**；包含全部 653 个 shape 时为 0.572。与 baseline 直接逐 shape 相除后，中位数如下（不能用上表两个中位数相除代替）：

| 卷积核 | opt / baseline 耗时中位数 |
| --- | ---: |
| 3×3 | 0.937 |
| 5×5 | 0.912 |
| 7×7 | 0.969 |
| 9×9 | 1.039 |
| 11×11 | 0.534 |

11×11 的 opt 耗时中位比值约为 baseline 的 53.4%，本轮优势明显；9×9 约为 103.9%，未表现出提升。其余组的差异较小，尤其 7×7，不将这次跨会话补测视为稳定的小幅收益证明。
